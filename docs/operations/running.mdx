      volumes:
        - ./fraise.config.toml:/etc/fraise/fraise.config.toml:ro

## Config file or flags

A config file is optional — the defaults plus flags are a complete configuration. **Mount one when you want to pin settings; use flags for the one or two you override per environment.**

```bash
fraise -config /etc/fraise/fraise.config.toml -log-level error
```

Flags win over the file. See [How configuration works](/docs/configuration/overview).

## Health checking the container

```yaml
healthcheck:
  test: ["CMD", "wget", "-qO-", "http://localhost:9876/"]
  interval: 10s
  timeout: 2s
  retries: 3
```

`GET /` is liveness and readiness in one — there is nothing to warm up and nothing to recover.

## Stopping it

`docker stop` sends SIGTERM, so the default path is the graceful one. It waits 10 seconds before SIGKILL by default — exactly the default `shutdown-grace` — so raise it with `--stop-timeout` or compose's `stop_grace_period`.

<Note title="Container stop timeout" type="warning">

  **Give the container a stop timeout longer than `shutdown-grace`**, or the runtime's SIGKILL will cut the drain short. See [Shutdown](/docs/operations/runbook/shutdown).

</Note>

## Not behind a load balancer

Two instances do not share memory. A client that wrote to one and recalls from the other gets nothing — see [Durability](/docs/operations/durability) before scaling horizontally.
