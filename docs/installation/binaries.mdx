## Download and run

<Step>
  <StepItem title="Pick the release and platform">

  ```sh
  VERSION=0.1.0
  OS=$(uname -s | tr '[:upper:]' '[:lower:]')                # linux | darwin
  ARCH=$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/')  # amd64 | arm64
  ASSET="fraise_${VERSION}_${OS}_${ARCH}.tar.gz"
  BASE="https://github.com/FraiseHQ/fraise/releases/download/v${VERSION}"
  ```

  </StepItem>
  <StepItem title="Download and unpack">

  ```sh
  curl -sSfLO "${BASE}/${ASSET}"
  tar xzf "$ASSET"
  ```

  </StepItem>
  <StepItem title="Run">

  ```sh
  ./fraise
  ```

  </StepItem>
</Step>

Windows builds ship as `.zip` under the same naming scheme.

## Verify a release

Releases carry a [cosign](https://docs.sigstore.dev/) signature over `checksums.txt`, using the same `VERSION` and `BASE` as above:

<Step>
  <StepItem title="Verify the checksum file">

  ```sh
  curl -sSfLO "${BASE}/checksums.txt"
  curl -sSfLO "${BASE}/checksums.txt.sigstore.json"

  # 1. the bundle proves checksums.txt came from this repo's release workflow
  cosign verify-blob \
    --bundle checksums.txt.sigstore.json \
    --certificate-identity-regexp 'https://github.com/FraiseHQ/fraise/.github/workflows/go.yaml@refs/tags/v.*' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com \
    checksums.txt
  ```

  </StepItem>
  <StepItem title="Verify the archive">

  ```sh
  # 2. checksums.txt proves your archive is the one it covers
  sha256sum --ignore-missing -c checksums.txt   # macOS: shasum -a 256 --ignore-missing -c
  ```

  </StepItem>
</Step>

The two steps chain: the first establishes that the checksum file came from the release workflow, the second that the archive on your disk is the one that file covers.

## Pointing it at a config

```sh
./fraise -config /etc/fraise/fraise.config.toml -log-level error
```

Flags and the config file name the same settings; flags win. See [How a value is resolved](/docs/configuration/overview).
