title: "Keywords"
description: "The reserved words of FQL, where they read as syntax and where as data, and how casing is treated"

Tokens form the vocabulary of the Fraise query language, in four classes: keywords, [identifiers](/docs/query-language/tokens/identifiers), [literals](/docs/query-language/tokens/literals) and [punctuation](/docs/query-language/tokens/punctuation).

Keywords are the commands and the field names. **A reserved word is syntax wherever a search term can stand; quote it to search for it**: `recall top` and `recall food topic` are errors, and `recall 'top'` searches for the word. After a field's `:` only a value can appear, so there a keyword is ordinary data: `entity:top` files under the word "top".

One tie-breaker resolves the boundary: **a keyword immediately followed by `:` is always a field**, so `top:3` never means the word "top", and `entity:top:3` is an error rather than a guess.

<Note title="Reserved but unimplemented" type="warning">

  `forget`, `update`, `describe` and `explain` are reserved by the lexer as well, but no command implements them: a query starting with either is rejected.

</Note>

## Casing

Keywords are written in lower case only, and casing does not un-reserve one: among a recall's terms, a mis-cased keyword is an error naming the casing — `recall x Since 7d` and `recall Top shelf` are rejected, never read as searches. Folding `Since` into a term would let a mistyped clause silently become data, scoping the query by nothing with no error to correct from.

The tie-breaker above is the one place casing is forgiven. A word glued to a `:` has exactly one reading — no production puts a bare word before a colon — so `Depth:2` is the depth clause, and `recall x depth:2 DEPTH:5` is reported as the duplicate it is rather than as a casing mistake. Blaming the casing there would name the shallower of the two problems, and an agent that lower-cased it would meet the duplicate only on its next try.

Forgiven is not unremarked: the clause runs and the response carries a [warning](/docs/query-language/reference/warnings) naming the casing. Away from a colon the spelling must still match exactly, so `RECALL x` is not a command.

## A keyword among the terms

`recall x since 7d` is one `:` away from `recall x since:7d`, and either reading, guessed, would answer a differently scoped question with nothing in the response to say so. So it is an error, and the message names both repairs, spelled with the word written after the keyword: `write since:7d if a filter was meant, or quote it ('since') to search the word`. A command word has no clause reading, so for `recall recall` the message names only the quote. Once a clause has started, a keyword without its `:` has one reading left, and the message names only that clause: `recall zebras since:7d topic food` asks for `topic:food`. See [Errors](/docs/http-api/errors).

## No boolean operators

There are none. Several terms in one recall are a union (any match seeds the search), and there is no way to write a conjunction or a negation.
