title: "Temporality"
description: "How age decays a fact's score, and how since/until differ from decay by being absolute constraints"
navIcon: "⏳"
---

Every fact carries the time it was written, and a recall's score decays with that age on an exponential half-life (`half-life`, one week by default): the score is multiplied by

$$
0.5^{\, \text{age} / \text{half-life}}
$$

So a fact twice the half-life old contributes a quarter of its score.

## Decay is ranking, not filtering

An old fact still surfaces when nothing newer matches, which is what makes it safe to leave on by default. A negative `half-life` disables decay entirely; zero, like any unset setting, means the default.

This is the "temporal" in temporal memory graph: recency is a first-class ranking signal, because contextual memory ages — what an agent learned an hour ago usually beats what it learned last quarter.

## `since:` and `until:` are absolute

Filtering is what the time bounds are for, and they are absolute constraints rather than nudges: **a fact outside the window does not appear at any score.**

Bounds are written as a duration read as "ago", or as a quoted date:

```text
recall billing since:7d
recall billing since:'2026-01-15' until:'2026-02-01'
```

| Form | Example | Meaning |
|---|---|---|
| duration | `since:7d` | no older than seven days |
| date | `since:'2026-01-15'` | on or after that day |
| date and time | `since:'2026-01-15T10:00:00Z'` | on or after that instant |

<Note title="Dates are quoted" type="warning">

  A date is always quoted: its `-` is not a word character, so a bare `since:2026-01-15` is rejected with an error showing the quoted form. Inside the quotes a time of day may follow, written as RFC3339. See [Literals](/docs/query-language/tokens/literals).

</Note>

## Choosing between them

| You want | Use |
|---|---|
| recent facts preferred, older ones still reachable | the default decay |
| a hard window, nothing outside it | `since:` / `until:` |
| no recency preference at all | a negative `half-life`, such as `-1h` |

`half-life` is an operator setting, not a query clause — see [Engine settings](/docs/configuration/reference/engine).
