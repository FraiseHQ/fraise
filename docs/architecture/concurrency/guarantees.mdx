## Per-graph atomicity

Every operation on a graph goes through its read-write lock:

- concurrent writes to the same graph **will serialize**;
- concurrent reads do not block each other;
- writes block concurrent reads.

## Cross-graph independence

Operations on different graphs are fully independent:

- 4 workers can write to 4 different graphs in parallel;
- no global coordination or lock contention.

## Stream ordering within a graph

The queue is FIFO: workers take streams in the order they were submitted. Execution order is not guaranteed, because several workers take from the queue at once and whichever reaches the graph's lock first runs first — `sync.RWMutex` makes no promise that acquisition follows arrival. **Streams in flight at the same time have no order between them, even on the same graph.**

What is guaranteed is that a request is answered only after its stream has been applied. An acknowledged write is therefore visible to every request sent after the acknowledgement.

<Note title="Ordering is the caller's" type="warning">

  When a sequence of writes matters, send each one after the previous one has answered. Running with `workers = 1` orders execution globally, at the cost of all concurrency.

</Note>

## Avoiding lock contention

1. **Distribute data** — use multiple graphs; partition by agent, conversation, or domain.
2. **Minimize lock hold time** — writes commit in place, so hold time is proportional to the fact being written; keep each fact to one self-contained statement.
3. **Watch for 429s** — they mean the queue is filling up; consider raising `buffer-size` or `workers`. If one *graph* is hot, more workers will not help — spread the load across graphs, which is what they are for.

## Future considerations

- **Write ordering** — provide a guarantee or API to enforce stream ordering across graphs
- **Lock profiling** — metrics for lock contention and wait times
- **Optimistic locking** — versioning for read-optimized workloads
- **Lock-free data structures** — alternatives like `sync.Map` for specific use cases
